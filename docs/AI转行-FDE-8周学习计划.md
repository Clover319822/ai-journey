# AI 转行 · FDE 方向 · 8 周学习计划

> 制定对象：31 岁 / 全日制大专 / 已婚 / 7 年餐饮管理（必胜客值班经理→餐厅经理 + 意大利菜西餐厅经理）/ 2 年+ TEMU 全托管 / 零编程基础
> 可用时间：每天 ≥ 8 小时（8 周约 450+ 小时）
> 目标：2 个月后具备可展示作品 + 可投递简历

---

## 一、先说真话：三个必须接受的现实

**1. "两个月后直接投 FDE 上岸"成功率接近 0。**

FDE（Forward Deployed Engineer，前置部署工程师）起源于 Palantir，现在 OpenAI、Anthropic 都在规模化招聘。这个岗位的本质是：把不成熟的 AI 能力，塞进客户混乱的真实业务里，并在现场把它跑通。它要求三种能力同时在线——

- 能写代码、能 debug、能做系统集成（工程能力）
- 能跟客户坐在一起把模糊需求拆成可交付的东西（咨询能力）
- 能扛住现场压力和不确定（抗压与 ownership）

你现在**第二、三条已经很强**（7 年门店管理就是天天干这个），**第一条是零**。两个月能补到"能交付简单应用"的水平，补不到"能独立扛客户项目"的水平。

**2. 学历是硬门槛，但不是死路。**

Anthropic / OpenAI 的 FDE 基本要名校 CS 背景 + 资深工程经验 + 英语流利 + 全球出差，这两年别想。但国内这条赛道的等价岗位大量存在且严重缺人，学历卡得松得多：

- AI 应用工程师 / AI 解决方案工程师 / 交付工程师
- 大模型厂商的解决方案团队（智谱、月之暗面、阿里、字节政企线、各家云智能）
- AI SaaS 公司的实施 / 技术型客户成功
- AI 代运营、数字化服务商的落地岗

**正确路径是两段式**：先拿"AI 应用 / 交付岗"进门（2-4 个月）→ 攒 1-2 年真实客户项目 → 再够 FDE。不要一步登天。

**3. 你最大的资产不是学习时间，是行业。**

科班转行者做作品，做的是"通用聊天机器人""PDF 问答"，烂大街。而你做过必胜客餐厅经理、做过 TEMU —— **餐饮门店运营** 和 **跨境电商运营** 是两个 AI 落地需求极大、但没人真正懂业务的领域。你能写出别人写不出来的东西。这是你唯一的差异化，必须押在这里。

## 二、定位：一句话定义你自己

不要说"我是自学转行 AI 的"。要说：

> **"我做过 7 年连锁餐饮门店管理，2 年跨境电商，现在做 AI 落地——我比纯工程师更懂业务现场，比业务方更懂怎么把 AI 落进流程。"**

这句话就是你的简历开头、GitHub 简介、面试开场白。所有作品都围绕它。

## 三、技术栈（别纠结，照这个选）

| 层 | 选择 | 理由 |
|---|---|---|
| 主语言 | **Python** | AI 生态第一语言，两个月只够精一门 |
| 次语言 | TypeScript（第 5 周后才碰，做前端） | 有精力再补，不强求 |
| 模型 API | **Anthropic Claude**（主力）+ DeepSeek / 通义千问（成本对照） | FDE 方向对齐 Anthropic；国产便宜用来跑量 |
| Agent 框架 | 先**手写循环**，再上 **LangGraph** | 先懂原理再用框架，否则只会调包 |
| 向量库 | **Chroma**（起步）→ pgvector（进阶） | 本地零配置，够用 |
| 前端 | **Streamlit**（前 6 周）→ Next.js（有余力再说） | Streamlit 一天能出可演示界面，速度优先 |
| 工具协议 | **MCP**（Model Context Protocol） | Anthropic 主推，FDE 高频词，必须会 |
| 评估 | **Langfuse** + 自建 eval 集 | 会不会做 eval，是业余和专业的分水岭 |
| 部署 | Docker + 一台云服务器（腾讯云轻量） | 作品必须能在线访问，不能只在本地跑 |
| 其他 | Git / GitHub / Linux 命令行 / HTTP & JSON | 基本功，第 1 周必须过 |

预算：API 费用 300-500 元/月，服务器 50 元/月。这是必要投入。

## 五、8 周逐周安排

### 第 1 周：工程地基（Python + Git + API）

- Python：数据类型、控制流、函数、文件读写、异常处理、requests、`async/await` 概念
- Git：init / add / commit / branch / push / PR，命令行而不是 GUI
- 命令行 & VS Code & uv/pip 环境管理
- HTTP / REST / JSON：能用 Python 调通任意 API
- **周末产出**：一个脚本，批量调大模型 API 改写 50 条 TEMU listing 标题，输出到 Excel
- 资源：CS50P（哈佛 Python 课，免费）、廖雪峰 Python 教程、Anthropic API 快速开始

### 第 2 周：LLM 核心能力

- Prompt Engineering：Anthropic 官方 prompt 教程（必读，反复读 3 遍）
- API 深入：system prompt、多轮 messages、temperature、streaming、token 计费
- **结构化输出 / JSON mode**（工程落地的命门）
- **Tool Use / Function Calling**：让模型调你的函数
- **周末产出**：把第 1 周的脚本升级成"Listing 生成器 + 违规词检测"，输出严格 JSON，带重试与容错
- 概念：把"写一个好 prompt"当成"写一份给新员工的操作手册"——你的餐厅 SOP 经验直接迁移

### 第 3 周：RAG（检索增强生成）

- Embedding 原理、相似度计算
- Chunking 策略（固定 / 语义 / 按结构），这是 RAG 好坏的第一变量
- 向量库 Chroma 实操
- 检索进阶：BM25 + 向量混合检索、Rerank 重排、引用溯源、幻觉抑制
- **周末产出**：**【作品 A】餐饮运营知识库 RAG** —— 把门店 SOP、食品安全规范、排班规则、客诉处理手册做成知识库问答，每条回答带出处页码
  - 数据从哪来：你自己写（你背得出），+ 公开食安规范 + 开源餐饮管理文档
  - 这是别人做不出来的：只有你知道门店真实会问什么

### 第 4 周：Agent（智能体）

- 手写 ReAct 循环：思考 → 调工具 → 观察 → 再思考（**先不用框架**）
- 再上 LangGraph：状态机、条件分支、人工介入（human-in-the-loop）
- **MCP**：概念 + 自己写一个 MCP server（比如接餐厅库存表）
- 多轮对话状态管理、错误恢复、成本控制（防止死循环烧钱）
- **周末产出**：把作品 A 升级为 Agent —— 不只问答，能"执行"：查库存、生成检查表、输出值班日报

### 第 5 周：工程化与评估（决定专业度的一周）

- **Eval**：建 50-100 条测试集，量化准确率、召回率、有用率。做前后对比实验（换 chunking 策略前 vs 后）
- 可观测性：Langfuse 记录每次调用的 prompt、token、耗时、成本
- Docker 打包、环境变量、日志、错误处理
- 部署上线：作品 A 部署到公网，能给别人打开链接直接用
- TypeScript / Next.js（有余力学，没余力跳过）

### 第 6 周：【作品 B】餐饮门店运营 Agent（杀手锏，全力做）

这是你简历的核心。做一个"餐饮店长 AI 助手"，功能至少包含：

1. **智能排班**：输入历史客流 + 员工技能 + 人力成本上限 → 输出排班表 + 成本测算
2. **订货量建议**：基于历史销量 + 天气/节假日 + 损耗率 → 输出订货单
3. **客诉处理**：输入客诉内容 → 输出处理话术 + 是否升级 + 补偿方案建议（区分客诉等级）
4. **值班日报自动生成**：把当日数据变成给区域经理看的汇报

- 必须有 UI（Streamlit 即可），必须能在线访问
- 必须有 eval 数据：比如"排班建议相比人工排班，人力成本降低 X%"
- **README 里必须写清楚业务规则从哪来**——来自你 7 年门店经验，这是纯工程师写不出来的部分

### 第 7 周：【作品 C】跨境电商运营 Agent

1. **选品分析**：输入品类 → 输出价格带分布、竞品情况、加价率测算、风险提示
2. **Listing 多语言生成 + 平台违规词检测**
3. **备货 / JIT 提醒**：基于销量与库存周转
4. 录一段 **3 分钟 demo 视频**（口播 + 屏幕录制），讲清楚它解决什么真实痛点

这个作品的价值在于：你自己就是用户。你能说清"我以前每天花 3 小时干这件事，现在 10 分钟"。

### 第 8 周：包装与投递

- GitHub 主页整理：3 个仓库，每个 README 含——解决什么问题 / 架构图 / 效果对比数据 / 怎么跑起来
- 写 3-5 篇文章发在掘金/知乎/即刻/小红书，其中一篇必须是：**《一个做了 7 年餐厅经理的人，为什么来写 AI》**。这篇是你的敲门砖，比简历管用
- 简历改造（见下表）
- 开始投递 + 每日复盘

## 七、投递策略（不要海投）

1. **目标公司**：50 人以下的 AI 创业公司、AI SaaS、大模型厂商的交付/解决方案团队、AI 代运营服务商。大厂社招学历卡死，别浪费时间
2. **渠道优先级**：内推 > 发作品给创始人/技术负责人（直接私信，附上 demo 链接）> 垂直社群 > 招聘平台
3. **话术**：不要说"我自学了两个月"，要说"我做了 7 年餐饮、2 年跨境，我用 AI 把我自己的老本行重做了一遍，这是 demo"
4. **预期管理**：投 100 份，能有 5-10 个面试算正常。大专 + 31 岁 + 零经验，靠的是作品破格，不是靠简历过筛
5. **备选路径（强烈建议并行）**：接小单。帮餐饮商家做 AI 客服、帮跨境卖家做 listing 工具，哪怕一单 2000 块。**一个真实付费客户案例，比三个自嗨作品有用十倍**，而且直接证明你有交付能力——这正是 FDE 的核心
