## 二、今日主题：结构化输出（JSON mode）

第 2 周的核心就两个字：**可控**。

现在的 `temu_copilot.py` 输出的是 Markdown 文本。文本有个致命问题：
**机器读不了。** 你想把"下一步 = 放弃"这个字段自动筛出来、想把 8 个 SKU 的结论汇成一张表、
想统计退货风险点出现频率——全都做不到，只能人眼看。

这是业余作品和专业作品的分水岭。今天把它跨过去。

概念先立住：**别再让模型写作文，让模型填表。**
你给它的不是"写一张评估卡"，而是"按这个字段定义返回 JSON"。
就像你在必胜客给新来的值班经理一份《闭班检查表》——不是让他写感想，是让他一格一格打勾。

## 四、下午 3h：改代码（4 个动作，都在 temu_copilot.py 里）

### 动作 1：加 schema 常量（放在 build_prompt 上面）

```python
JSON_SCHEMA = """{
  "sku": "字符串，品名",
  "verdict": "只能是 go / optimize / drop 三者之一",
  "verdict_reason": "字符串，一句话理由，不超过 40 字",
  "return_risks": [{"risk": "风险描述", "action": "规避动作"}],
  "titles": ["3 个英文标题，每个不超过 80 字符，不用 best / No.1 这类违禁词"],
  "selling_points": ["3 条中文卖点，每条不超过 25 字"],
  "next_step": "字符串，具体到能直接执行"
}"""
```

### 动作 2：写 build_json_prompt()（照抄 build_prompt 的结构，改输出要求）

把原来 `【输出格式】Markdown...` 那一整段替换成：

```
【输出格式】只输出一个 JSON 对象，不要 Markdown 代码块，不要任何解释文字。
字段定义如下：
{JSON_SCHEMA}
```

同时加一条硬规则：**"verdict 字段的值只能是 go / optimize / drop，不许自创。"**

### 动作 3：写 parse_json()（这是今天的重点，容错全在这里）

```python
import json
import re

def parse_json(text: str) -> dict | None:
    """把模型的返回文本解析成 dict。模型不老实是常态，这里兜住三种脏数据。"""
    t = text.strip()
    # 1. 去掉 ```json ... ``` 围栏
    t = re.sub(r"^```(?:json)?\s*|\s*```$", "", t, flags=re.MULTILINE).strip()
    # 2. 掐头去尾：取第一个 { 到最后一个 }
    if "{" in t and "}" in t:
        t = t[t.index("{"): t.rindex("}") + 1]
    try:
        return json.loads(t)
    except json.JSONDecodeError as e:
        print(f"    JSON 解析失败：{e}")
        return None
```

### 动作 4：加 --json 开关

在 `main()` 的 argparse 里加一行：

```python
parser.add_argument("--json", action="store_true", help="输出 JSON 而不是 Markdown")
```

在 `ask_llm` 的重试逻辑里加一层：**如果 parse 出来是 None，就把"上一次返回不是合法 JSON，错误是 xxx，请只输出 JSON"塞回 prompt 再试一次**。原来只重试网络错误，现在连"模型不听话"也重试——这才是"带重试与容错"。

最后把结果写成 `week02/output/评估卡-<时间戳>.json`：

```python
out = OUT_DIR / f"评估卡-{ts}.json"
out.write_text(json.dumps(records, ensure_ascii=False, indent=2), encoding="utf-8")
```
